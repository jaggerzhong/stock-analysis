# 股票与加密资产的支撑、阻力区计算

用于“上方压力在哪”“下次最大阻力”“支撑位”及突破确认。先说明分析周期：未来几天的反弹、几周的波段，或数月的趋势。股票与BTC共用价格行为框架，但数据覆盖、交易时段和事件影响必须分别处理。技术阻力不等于合理价值上沿，也不自动构成买卖建议。

## 数据与时点

- 更新现价，标注来源、交易对/币种、时间和时区。优先使用可用的Longbridge行情；加密交易对为空或无权限时，使用交易所公开现货API等来源，并披露替代来源。刷新失败时明确旧快照时间，不称为实时。
- 取得足以覆盖分析周期的小时/更细K线及日线；排除未收盘K线和截止时间之后的样本。用于判断摆动高低点的右侧确认K线也必须已收盘，避免使用未来信息。
- 保留原始数据、查询窗口、成交量单位、价格复权方式和计算参数。不足一个窗口时披露实际覆盖，不把1000根小时线自动称为90天。
- 不将来源不同的成交量直接拼接。逐笔成交可生成精细逐价分布；只有OHLCV时必须称为“按K线估算的成交分布”。

## 可复算成交分布

至少比较两个与目标周期有关的窗口以及不同分箱宽度；例如短期、一个月和更长窗口，而不是固定沿用某次BTC的天数或价位。宽度按标的价格、波动率和数据精度选择。窗口、箱宽、箱起点都会影响结果，应检查半个箱宽偏移是否改变主要区域。窗口之间高度重叠，不算独立证据。

对每根K线，最高价H、最低价L、收盘C、基础资产/股数成交量V。对价格箱[a,b)：

```text
K线范围均匀估算：V_bin = V × max(0, min(H,b) - max(L,a)) / (H-L)
典型价敏感性检查：将V全部归入含(H+L+C)/3的价格箱
H=L时：全部归入包含该价格的箱，避免除零及成交量丢失
窗口内占比：箱或连续区域的估算成交量 / 同一窗口总成交量
```

均匀分配是假设，不代表每个价位真实成交相等；典型价法同样是近似。细K线通常比日线更适合估算，但不能因此声称是逐笔数据。使用同一单位；不要混用BTC数量、合约张数、美元成交额或股票换手率。先计算整个窗口分布，不能把上方箱重新归一化后误报占全市场的比例。

找出成交峰值箱（POC）及相邻高成交箱，组成候选区域。POC可能在现价下方；它本身既不意味着阻力，也不意味着支撑。对于上方阻力，只比较现价上方或价格正接近的区域，并明确穿越现价的箱。若最大峰值在下方，不把它称作“最大上方阻力”。

## 交叉确认和排序

1. 标出已确认的摆动前高/低点、此前盘整平台、失守后的支撑转阻力；列出发生日期与价格，避免只画整数关口。
2. 从已收盘日线/4小时线计算适当均线，例如20、50、200期。标注周期与均线类型，不混同小时MA200与日线MA200。
3. 检查候选成交区是否与前高、平台、均线或有依据的缺口重合。连续相邻箱应合并观察，避免把同一平台拆成数个看似独立的证据。
4. 分别报告最近阻力、中间压力和指定窗口内的主要阻力候选。优先关注跨参数稳定、且有其他价格结构支持的区域；仅一个分箱峰值不足以称“最大阻力”。不以未经回测的加权分数声称成功概率。
5. 若不同窗口指向不同位置，同时呈现：较近窗口用于近期反弹，较长窗口用于远端压力。无稳定结果时降低置信度，不挑选最符合预设答案的窗口。

阻力带宽结合箱宽、实际波动和ATR；不要给远超数据精度的小数价格。“最大”只表示当前数据范围内证据较强，既非价格上限，也非一定到达的目标。

## BTC与股票的差异

| 项目 | BTC等加密资产 | 股票 |
|---|---|---|
| 时间 | 24×7；明确日线UTC等收盘时区；200日覆盖200个自然日 | 按交易日/会话计算；200日为200个交易日，约九个多月 |
| 成交覆盖 | 单交易所现货不代表全市场；BTC/USD与BTC/USDT有基差；现货与永续分开 | 优先综合成交源；明确常规/盘前盘后，集合竞价处理与数据缺口 |
| 公司行动 | 核查代币单位、交易对变化或异常数据 | 价格与股数成交量必须处于一致拆股/复权口径；仅复权价格会扭曲旧量分布；现金分红缺口需说明 |
| 事件 | 交易平台、监管、流动性与杠杆可能迅速改变结构 | 财报、指引、并购、增发和解禁可能使旧价格区失效；结合最新公告 |
| 成本代理 | URPD是UTXO链上移动价格分布，转账不等于买入；实现价格是特定群体平均成本 | 成交/“筹码分布”不是真实股东成本或仍在持有的股份台账 |
| 衍生品 | 资金费率、OI、清算估计是辅助；空头清算可带来买盘，不直接等同卖压 | 期权OI不能单独推导压制；需看净Gamma、交易商方向及到期时间 |
| 缺口 | 连续现货通常缺少休市跳空；CME期货缺口须独立标明来源 | 隔夜财报等跳空常见；无必然回补保证 |

挂单可撤；订单簿卖墙只能代表当时可见流动性。链上、期权、清算或全市场数据没查到，就明确未验证，不借其名义提高置信度。对股票，价值与技术分别判断：盈利改善可以推动突破历史阻力，高估也不保证立即下跌。

## 确认、失效与交付

给出与用户周期一致的确认条件，例如4小时/日线收在区域上沿以上、回踩守住，并有相对同周期历史成交量的支持；具体条件是分析判断，不保证避免假突破。盘中触碰或短暂刺穿不等于确认。突破后旧阻力可能变支撑；基本面、价格结构或市场流动性变化时重新评估。

用户看到的结果应包括：

- 现价及时间、时间窗口、来源/覆盖、计算精度；
- 由近到远的区域表：距离现价、成交分布/日期前高/均线等依据；
- 指定窗口的主要候选与置信度、参数敏感性及缺失数据；
- 突破与失效条件、必要时最近的下方结构，不把远端阻力写成必到目标。

不要从同一资产重复指标推导独立验证；不要由阻力位自动发出追涨、做空或补仓指令。需要操作建议时仍遵守skill的数据质量、基本面和仓位约束。

## 离线计算工具

`scripts/volume_profile.py`只计算候选成交箱与敏感性，不联网、不读取账户、不自动选择“最大阻力”，也不修改主分析器评分。复核前高和均线后再解释输出。

输入为JSON数组，每条采用下列规范字段。时间为带时区ISO8601；`close_time`是该K线结束边界（不包含边界）。使用真实交易会话，不把股票日线机械加24小时来推测收盘。Longbridge等输出缺少收盘时间时，先按市场日历和会话归一化；不要猜测未收盘K线状态。

```json
[{"open_time":"2026-01-05T14:30:00Z","close_time":"2026-01-05T15:30:00Z",
  "open":100,"high":104,"low":99,"close":102,"volume":12000}]
```

也支持币安原始K线JSON数组（开盘毫秒、OHLCV、结束毫秒等），使用`--input-format binance`；其毫秒结束时间按结束边界加1毫秒处理。只混合一个交易对/周期/会话/复权口径。以下是参数示例，按实际标的、数据时点和价格尺度替换：

```bash
python3 scripts/volume_profile.py data/bars.json \
  --as-of 2026-02-01T00:00:00Z --lookbacks 7 30 \
  --bin-widths 1 2 4 --source 'provider / symbol / spot or equity' \
  --volume-unit shares > data/profile.json
```

lookbacks单位为自然日，依时间戳过滤，不用`天数×24`截股票小时K线。窗口包含开盘时间在起点及以后、且在截止时间前已经收盘的完整K线；跨窗口起点的K线不拆分。输出实际首末时间和起点覆盖标志；该标志不证明会话中无缺失K线。工具默认同时比较均匀/典型价两种估算及箱起点0/半箱偏移，保留完整分布和POC占比。实际成交覆盖与数据缺失仍需调用方核对。
